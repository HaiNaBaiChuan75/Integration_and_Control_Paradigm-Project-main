# 2026-06-27 GeckoLib 集成与 SubLevel 渲染验证

## 背景

为未来使用 GeckoLib 动画模型替换当前的 2-SubLevel + 2-Constraint 炮塔方案做技术验证。
参考了 Oritech 的 Controller + Core 多方块架构模式和 Crossout "运动学武器装饰器"设计模式。

## GeckoLib 依赖引入

- 在 `build.gradle` 中添加 CloudSmith Maven 仓库和 `geckolib-neoforge-1.21.1-4.6.6` 依赖
- 在 `gradle.properties` 中添加 `geckolib_version=4.6.6`
- CloudSmith Maven 需 VPN 才能解析，首次构建需清除配置缓存

## TestController 测试方块

创建了完整的 GeckoLib 测试结构：

### 踩坑记录

1. **Registrate 冲突**：`EntityBlock` 与 `DeferredRegister` 的 `registerBlock` 默认注册器冲突，需用 `registerBlock(name, blockSupplier, properties)` 而非 `register(name, blockSupplier, properties)`
2. **创造标签页崩溃**：`IllegalArgumentException: The stack count must be 1` — 测试方块不能加入创造标签页（原因未深究），用 `/give` 获取
3. **BlockItem 未注册**：`/give @s iac_p:test_controller` 无效 — 需在 `ModItems` 中注册 `ITEMS.registerSimpleBlockItem()`
4. **DefaultedBlockGeoModel 路径规则**：模型路径自动构造为 `geo/block/{name}.geo.json`（多了 `block/`），文件需放在 `geo/block/` 下

### DefaultedBlockGeoModel 路径规则

| 资源类型 | 实际路径 | 构造参数 |
|---------|---------|---------|
| 模型 | `geo/block/test_controller.geo.json` | `ResourceLocation("iac_p", "test_controller")` |
| 纹理 | `textures/block/test_controller.png` | 同上 |
| 动画 | `animations/block/test_controller.animation.json` | 同上 |

### 注册链

```
ModBlocks.TEST_CONTROLLER
  → ModItems.TEST_CONTROLLER (registerSimpleBlockItem)
    → ModTestControllerBlockEntityTypes.TEST_CONTROLLER
      → IACP.java: modEventBus 注册 BE 类型
        → IACPClient.java: EntityRenderersEvent.RegisterRenderers 注册渲染器
```

## 验证结论

- ✅ GeckoLib `GeoBlockRenderer` 在普通世界中渲染正常
- ✅ 在 Sable SubLevel 内部渲染正常，旋转动画正常，跟随 SubLevel 变换
- ✅ GeckoLib 与 SubLevel 渲染管线完全兼容
