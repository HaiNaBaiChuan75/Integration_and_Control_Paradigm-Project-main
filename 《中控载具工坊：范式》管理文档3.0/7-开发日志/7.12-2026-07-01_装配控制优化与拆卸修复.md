# 2026-07-01 装配触发优化与拆卸逻辑修复

## 背景

06-30 实现的 Physics Assembler 使用服务端手动 3 格射线检测来定位座舱。这种方式绕了弯路——客户端 `mc.hitResult` 已经知道玩家在看什么方块。同时，拆卸逻辑（SubLevel → 主世界）存在两个 Bug。

---

## 装配触发优化：消除服务端射线检测

### 问题

原实现：客户端发送空信号 → 服务端做 3 格 `level.clip()` 找座舱。客户端已有的 `mc.hitResult` 信息被丢弃了。

### 方案

采用 **方案 A（数据包携带 BlockPos）**：
- 客户端检测 Ctrl+右键时，从 `mc.hitResult` 读取命中方块的 BlockPos
- 发送 `PhysicsAssembleC2SPacket(@Nullable BlockPos hitPos)` 到服务端
- 服务端有 `hitPos` 时直接调用 `handleAssembleOrDisassemble()`，零射线检测
- `hitPos == null` 时回退到 SubLevel 感知射线检测（拆解已装配结构）

**涉及文件**：
- `network/packets/PhysicsAssembleC2SPacket.java` — 从空 record 改为带 `@Nullable BlockPos` 的 record，自定义 StreamCodec
- `client/ClientEvents.java` — Ctrl+右键时从 `mc.hitResult` 读取 BlockPos
- `events/PhysicsAssembleHandler.java` — `handleAssembleSignal` 新增 `@Nullable BlockPos` 参数

### 第一次 Bug：拆解路径被截断

`handleAssembleSignal` 在 `hitPos != null` 时直接调用 `handleAssembleOrDisassemble()` 并 `return`，不再走 SubLevel 射线检测。但当玩家瞄准 SubLevel（已装配结构）时，`mc.hitResult` 可能穿透 SubLevel 线框命中后面的主世界方块，导致 `hitPos` 为一个无效坐标（非座舱、非 SubLevel），`handleAssembleOrDisassemble` 返回后 SubLevel 射线检测**永远不执行**。

**修复**：`handleAssembleOrDisassemble` 返回 `boolean`，`handleAssembleSignal` 在返回 `false` 时回退到 SubLevel 射线检测。

---

## 第二次 Bug：拆卸后方块消失

### 症状

拆卸触发成功（SubLevel 被移除），但没有任何方块被放回主世界，结构凭空消失。

### 根因

`SubLevelAssemblyHelper.moveBlocks()` 的内部流程是：**放置到新位置 → 清除旧位置**。当 SubLevel 未移动（刚装配即拆解）时，PD 伺服对齐的目标与当前位姿一致，约束力为零，`logicalPose` 不变。`AssemblyTransform` 计算出的新位置 == 旧位置，方块被放置后立即在同一位置被清除。

同时，`removeSubLevel()` 会调用 `plot.onRemove()` → `LevelPlot.onRemoveChunkHolder()` → `serverLevel.unload(chunk)`，将 Plot 区块从世界中卸载。若方块未被 `moveBlocks` 移到不同的世界区块，会随 Plot 区块一起丢失。

### 修复

完全参照 Simulated-Project 的 `SimAssemblyHelper.disassembleSubLevel()` 实现重构拆卸逻辑：

| 项目 | 修改前 | 修改后 |
|------|--------|--------|
| 锚点坐标 | `triggerPos`（玩家射线命中点） | `plot.getCenterBlock()`（Plot 中心，类比 Simulated 的组装器方块固定坐标） |
| `moveBlocks` | 仅在非 Identity 时调用 | **始终调用**（与 Simulated 一致） |
| `removeSubLevel` | **调用** | **不调用**（与 Simulated 一致） |

**关键发现**：`LevelPlot.onRemove()` 会执行 `serverLevel.unload()` 卸载区块，导致方块随 Plot 丢失。Simulated 从不调用 `removeSubLevel`，空的 SubLevel 留在原地不影响后续操作。

**代价**：刚装配即拆解时（Identity 情形），`moveBlocks` 仍会清除方块（与 Simulated 行为一致）。实际使用中车辆会先开动再拆解，此时 `logicalPose` 已变化，`moveBlocks` 正常将方块放到新的世界位置。

**参考实现**：
- `Simulated-Project: content/blocks/physics_assembler/PhysicsAssemblerBlockEntity.java`
- `Simulated-Project: util/SimAssemblyHelper.java`
- `Sable: api/SubLevelAssemblyHelper.java`（`AssemblyTransform.apply()` 映射逻辑 + `moveBlocks` 放置→清除时序）
- `Sable: api/sublevel/SubLevelContainer.java`（`removeSubLevel` → `LevelPlot.onRemove()` → `serverLevel.unload()` 链）
