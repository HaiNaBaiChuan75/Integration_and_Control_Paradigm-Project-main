# 2026-06-27（午至深夜）炮塔架构重构：Crossout 风格单块炮塔

## 背景

在 7.9 验证了 GeckoLib + SubLevel 渲染兼容性后，正式开始将炮塔架构从"2-SubLevel + 2-Constraint" 重构为 Crossout 风格的"单块方块 + GeckoLib 动画视觉旋转"。

**旧架构问题**：
- 每个炮塔需要 3 个 SubLevel（底座地毯、砂轮方向机、避雷针高低机）
- 2 个物理约束（RotaryConstraint 方向机、GenericConstraint 高低机）
- 约束重连脆弱、PD 伺服参数敏感、物理 tick 开销大

**新架构目标**：
- 单方块 = 完整武器，无额外 SubLevel，无物理约束
- GeckoLib 动画驱动视觉旋转（yaw/pitch bone）
- ClearanceSolver 网格级旋转碰撞检测
- 摄像机角度平行瞄准（v3 方案）

## 渲染管道修复

GeckoLib 4.6.6 的渲染管道顺序：

```
preRender()  →  设置骨骼旋转（旧方案）
    ↓
actuallyRender() → handleAnimations()  →  动画系统覆盖骨骼旋转为 [0,0,0]
    ↓
renderRecursively()  →  实际渲染骨骼
```

**修复**：将骨骼旋转从 `preRender` 移到 `renderRecursively`，在 `handleAnimations` 之后注入自定义旋转值。

## 瞄准系统演进（Crossout 风格 TurretTest）

### 客户端数据流
```
CameraMixin (每帧)    onClientTick (20Hz)    MachineGunTargetC2SPacket    服务端 handler
     │                      │                       │                         │
     │ 轨道球面坐标           │ hitPos + camYaw/Pitch │ worldToLocal             │
     │ lookDir + position ──→│ ────────────────────→│ hitLocal = Q⁻¹·(P-T) ──→│
     │                       │  5 float              │                         │ atan2(hitLocal)
     │                       │                       │                         │ driveImmediate()
```

### 瞄准迭代（Crossout TurretTest）

| # | 方案 | 结果 | 根因 |
|:-:|------|:----:|------|
| v1 | 命中坐标 → worldToLocal → atan2(hitLocal - weaopnLocal) | ❌ 抖动 | `entry.blockPos()` plot 大数目坐标与 hitWorld 相减后旋转产生数值敏感 |
| v2 | 命中坐标 → worldToLocal → atan2(hitLocal)（去掉 weaponLocal 减法） | ❌ 方向相反 | GeckoLib `setRotY()` 使用右手系 CCW+，与 MC CW+ 相反 |
| v3 | `atan2(dx, dz)` → `atan2(-dx, -dz)`（取反 ＋180°） | ❌ 背面朝向目标 | 模型默认朝向 Z-（北），atan2 零位为 Z+（南） |
| **v4（最终）** | **`atan2(-hitLocal.x, -hitLocal.z)`（取反向量）** | **✅ 瞄准正确** | **模型 Z- 零位 + GeckoLib CCW+ 双因素综合** |

### 关键发现
1. **`player.getYRot()` ≠ 摄像机实际朝向**：轨道摄像机模式下 `player.getYRot()` 控制的是摄像机在球面上的**位置**而非**朝向**。实际朝向被 CameraMixin 的 `setRotation(lookYaw, lookPitch)` 覆盖。必须从 `Minecraft.getInstance().gameRenderer.getMainCamera()` 获取。
2. **GeckoLib `setRotY()` 使用右手系 CCW+**：与 MC 约定（CW+）相反。`atan2` 输出 CCW+，因此直接使用不加负号。
3. **模型默认朝向 Z-（北）**：`atan2` 的零位是 Z+（南），需要取反方向向量等效 ＋180°。

## 性能问题

### ClearanceSolver 导致服务端卡顿
`TurretClearanceSolver.computeAll()` 在服务端主线程每 10 tick 执行：
- `collectOccupiedBlocks()`：17×17×17 三重循环 ≈2000 次 `level.getBlockState()`
- 偏航采样：360°/5° = 72 角度 × footprint 5 位置 = 360 次变换
- 俯仰采样：60°/5° = 12 角度 × footprint 5 位置 = 60 次变换
- `computeFreeYawRanges` + `computeFreePitchRanges` 各调用一次 collectOccupiedBlocks

**当前处理**：临时跳过 ClearanceSolver，直接直通。

### 动画文件格式问题
`turret_test.animation.json` 使用 BlockBench 导出的 `"vector"` 非标准语法，GeckoLib 4.6.6 无法解析。
- 修复：改用标准 Bedrock 关键帧格式
- geo.json identifier：`"geometry.unknown"` → `"iac_p:turret_test"`

## 遗留问题

- ⏳ 炮塔旋转微小抖动（客户端比服务端多跑 1-2 tick 旋转，纯动画骨骼无法物理平滑）

- ⏳ 测距汇聚（交叉火力）尚未实现
